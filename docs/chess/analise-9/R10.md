### O5. `reader_version` mais novo que o código (§2.10; `trocas.py` O5.1)

O §2.10 só trata a versão gravada **menor**, que é recasada. Entre o L1b, o L2 e o L3, cada PR sobe o `READER_VERSION`, e todos os builds leem `reference` v2. Então um build anterior (o `anterior-…` do usuário, ou uma CLI de outro worktree) aplica por `(page, block, inline)` decisões recasadas para uma segmentação mais nova. É o mesmo "Nf3 noutro lance" que o §2.10 descreve para os builds ≤ `cc2d484c`, agora entre builds novos. **Texto novo** depois de "e grava a nova.": `quando é **maior** que a do código (…), o arquivo abre só para leitura, como \`Read::Newer\`, e nenhuma decisão é aplicada por endereço (todas contadas em \`decisions_unmatched\`, motivo "gravadas por uma leitura mais nova"). A regra nasce no L1b, o primeiro PR que grava \`reader_version\`.` A Reversão do L0 e do L1 (O6) se apoia nela.
